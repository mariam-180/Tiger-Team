# طريقة عمل الموقع حاليًا

الموقع فيه واجهة للزائر والعميل، ولوحة منفصلة للأدمن. الواجهة بتعرض البيانات وتبعت الطلبات للـ API، والباك إند بيتحقق من الصلاحيات والتوافر والأسعار ويحفظ التغييرات في قاعدة البيانات. تغيير من الأدمن يظهر للعميل عند تحميل البيانات أو تحديثها؛ مش كل الشاشات فيها تحديث لحظي.

## الزائر والعميل

1. الزائر يقدر يشوف Home والمنتجات والبطولات وLive والأسئلة الشائعة. المنتجات لا تظهر قبل اختيار فئة.
2. العميل يعمل Sign up، ويستخدم رابط تأكيد الإيميل، وبعدها يعمل Sign in. استرجاع الباسورد يستخدم رابطًا مؤقتًا يُستعمل مرة واحدة.
3. الحجز: اختيار فرع متاح، ثم الموعد والمدة، ثم فحص التوافر واختيار الجهاز أو الأجهزة، ومراجعة الملخص والتأكيد. الباك إند يفحص التعارض ويحسب السعر ويخصم الرصيد. Snokardo مقفول ولا يقبل حجوزات.
4. المنتجات: اختيار فئة، عرض التفاصيل، إضافة للسلة، ثم Checkout بعد تسجيل الدخول. الباك إند يستخدم سعر المنتج الحقيقي ويفحص المخزون وينشئ طلبًا بحالة Pending ويحدّث المخزون. إنشاء الطلب **ليس خصمًا من بطاقة بنكية ولا دليلًا أن العميل دفع إلكترونيًا**؛ مفيش بوابة دفع إلكتروني متوصلة حاليًا.
5. Profile يعرض بيانات العميل وحجوزاته وطلباته وتسجيلاته المرتبطة بحسابه. العميل لا يقدر يدخل إدارة المستخدمين أو التقارير أو يغيّر أسعار المنتجات.
6. Live يفحص حالة البث دوريًا ويعرضه لما يبدأ. نجاح قراءة إعدادات البث لا يعني إن فيه بث حقيقي شغال؛ لازم خادم البث وبرنامج نشر مثل OBS.
7. صفحة البطولة تعرض الموعد والعداد عندما يوجد موعد مضبوط، وتسجيل المشاركين مرتبط بالحدث المتاح. صفحة FAQ تقدم إجابات وإرشادات للعملاء.

## الأدمن

الأدمن يعمل Sign in بنفس صفحة تسجيل الدخول، لكن يتوجّه إلى `/admin`. صفحات الإدارة مش واجهة العميل، ولا يوجد اختيار لإنشاء موظفين من الواجهة. بيانات الدخول المحلية موجودة في الملف المتجاهل من Git: `.local/admin-access.txt`.

| القسم | استخدامه |
| --- | --- |
| Overview | اختصارات للأقسام مع شرح كل وظيفة؛ الكروت مش أقسام إضافية مكررة. |
| People & credit / Users | البحث عن الحسابات، تعديل بياناتها والرصيد المسجل. تعديل الرصيد يدويًا مش تحصيل فلوس تلقائيًا. حساب الأدمن لا يمكن حذفه من الشاشة أو تحويل نوعه منها. |
| Reservations | متابعة حجوزات الفروع المفتوحة. تعديل مواعيد الحجوزات المستقبلية يعيد فحص التوافر وحساب التكلفة والرصيد من الباك إند. الحجز الذي بدأ لا يقبل تعديل المواعيد. |
| Product orders | متابعة طلبات العملاء وتغيير حالتها حسب الانتقالات المسموح بها: Pending ثم Processing ثم Shipped ثم Delivered. الإلغاء متاح حسب الحالة، والباك إند يرفض التغييرات غير المسموح بها. |
| Product catalogue | إضافة وتعديل المنتجات والصور والأسعار والمخزون، واختيار فئة من الفئات الموجودة. لا يوجد حاليًا محرر فئات مستقل داخل هذه الشاشة. |
| Race registrations | اختيار حدث موجود ومراجعة تسجيلات المشاركين وتحديث حالتها. الشاشة الحالية ليست محررًا لإنشاء بطولة جديدة. |
| Live broadcast / Streaming setup | الحصول على عنوان خادم OBS ومفتاح البث وروابط المشاهدة. المفتاح سري؛ ظهور الإعدادات لا يبدأ البث بمفرده. |
| Site settings | تعديل إعدادات الموقع الحالية ومفاتيح الخصائص والتواريخ. أسماء الإعدادات مرتبطة بالكود، فلا تتغير عشوائيًا. |
| Activity reports | معرفة أي حساب عمل تعديلًا أو إنشاءً أو حذفًا، وعلى أي سجل وفي أي وقت، وعرض التفاصيل المسجلة. دي مش إحصاءات مبيعات أو زيارات. |

### مفاتيح شاشة الحجوزات

- **Include ended bookings:** ضم الحجوزات المنتهية للقائمة.
- **Reviewed:** علامة أن الأدمن راجع هذا الإصدار من الحجز أثناء الزيارة الحالية. مش حالة دفع ولا تأكيد حجز، وليست محفوظة كتغيير على الحجز في الباك إند.
- **Unreviewed only:** إظهار الحجوزات التي لم تُراجع فقط. لو بيانات الحجز اتغيرت، يحتاج مراجعة مرة أخرى.

### التقارير والفلاتر

قسم الأنشطة الذي كان موجودًا في Users انتقل إلى Reports. Changed by هو الحساب الذي نفّذ العملية، وAction نوع العملية، وArea نوع السجل، والتواريخ تحدد المدة المطلوبة. Apply filters ينفّذ الاختيارات وReset filters يلغيها. View changes يعرض التفاصيل المسجلة لو موجودة.

## ما يحتاج إعدادًا أو قرارًا قبل التشغيل الحقيقي

- **البريد:** وضع التشغيل الحالي `EMAIL_DELIVERY=file`، يعني ملفات معاينة فقط. توصيل SMTP حقيقي لازم لإرسال تأكيد الحساب واسترجاع الباسورد إلى صناديق البريد.
- **الدفع:** الحجوزات تعتمد حاليًا على الرصيد. طلبات المنتجات تُنشأ وتؤثر على المخزون، لكن لا تتصل ببوابة دفع. صاحب الموقع يحتاج يحدد طريقة تحصيل الفلوس وإضافة الرصيد وسياسة الإلغاء والاسترجاع.
- **البث:** يحتاج خادم البث وOBS أو ناشر فعلي، واختبار مشاهدة بث حقيقي.
- **النشر:** الاختبارات المحلية لا تثبت إعدادات السيرفر المنشور والدومين وHTTPS والبريد في الإنتاج؛ يجب التحقق منها عند النشر.

## التحقق المنفّذ

اختبارات منفصلة تستخدم قاعدة بيانات اختبار وتغطي تغيير سعر منتج من الأدمن وقراءته من العميل، وإنشاء طلب ومتابعة حالته من الطرفين، وتعديل الرصيد والحجز وإعادة حساب التكلفة، ورفض صلاحيات العميل على الإدارة. تمت أيضًا قراءة البيانات العامة وبيانات الإدارة عبر Vite والـ API الجاريين محليًا، والتحقق من رفض الطلبات غير المسجلة للبيانات المحمية. فحص العرض البرمجي لا يغني عن مراجعة بصرية وتفاعلية في المتصفح على المقاسات المطلوبة.
